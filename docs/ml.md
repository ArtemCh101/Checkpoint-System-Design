# CV/ML Architecture: ml.md

## 1. CV/ML Tasks & Cascade Approach

Конвейер состоит из последовательных узкоспециализированных этапов для обеспечения предсказуемой задержки и независимой отладки:

* **Frame Quality Gate (CR-FIQA / Laplacian Variance)**: Оценка размытия и распознаваемости. Фильтрует некачественные кадры до запуска тяжелых нейросетей.
* **Detection & Alignment (SCRFD)**: Локализация лица и 5 ключевых точек (глаза, нос, углы рта). SCRFD выбран за точность и высокую скорость при квантовании.
* **Alignment Transformation (WarpAffine)**: Приведение кропа к каноническому размеру 112x112 px по ключевым точкам для стабильности Liveness и ArcFace.
* **Liveness / Anti-Spoofing (MiniFASNetV2)**: Классификация признака живого присутствия на кропе 112x112 px. Отсекает 2D-атаки (печать, фото с экрана).
* **Embedding Extraction (ArcFace ResNet-50)**: Извлечение 512D вектора с L2-нормализацией. Additive Angular Margin Loss обеспечивает высокое межклассовое разделение.
* **Vector Matching (FAISS IndexFlatIP)**: Скалярное произведение вектора с локальной базой в RAM.

## 2. Verification vs Identification

Основной режим — Identification (1:N) для бесконтактного и быстрого прохода. Verification (1:1) используется как резервный режим при проходе по RFID-карте.

## 3. One-to-Many Search on Large Scale

* **FAISS IndexFlatIP в RAM**: Используется для базы данных на Edge.
* **Ресурсы и скорость**: 12 000 векторов формата float32 занимают порядка 24.5 МБ RAM, время сканирования составляет менее 2 мс на CPU.
* **Масштабирование**: При увеличении базы более 100 000 векторов выполняется переход на графовый индекс IndexHNSWFlat с O(log N) сложностью.

## 4. Threshold Calibration & Error Trade-offs (FAR / FRR)

* **ALLOW (`score >= 0.65` AND `liveness >= 0.85`)**: Автоматический проход.
* **REVIEW (`0.50 <= score < 0.65` AND `liveness >= 0.85`)**: Серая зона. Автоматическое открытие блокируется, кадр направляется на ручную проверку охране.
* **DENY (`score < 0.50` OR `liveness < 0.85`)**: Отказ в доступе.
* **FAR vs FRR**: Приоритет системы — жесткая минимизация FAR (<= 10^-5), так как пропуск постороннего является критическим инцидентом. Ошибки FRR компенсируются серой зоной и быстрым подтверждением оператором охраны.

## 5. Rules vs Models Split

* **Модели (вероятностный контур)**: Детекция, оценка качества, классификация Liveness, извлечение 512D векторов.
* **Правила / Policy Engine (детерминированный контур)**: Проверка зон доступа, агрегация порогов ( score + liveness ), обработка таймаутов (150 мс) и отправка управляющего импульса на реле.

## 6. Pretrained Models vs Custom Data

* **Готовые модели (Off-the-shelf)**: SCRFD (детектор) и ArcFace ResNet-50 (экстрактор векторов). Извлечение универсальных биометрических признаков не требует переобучения под конкретный объект.
* **Собственные данные и калибровка**: MiniFASNetV2 (Liveness) дообучается на кадрах целевых камер с учетом специфики их IR-подсветки, углов установки и местного освещения. Пороги схожести и качества валидируются на целевой популяции сотрудников.

## 7. Baselines & Technical Metrics

* **Baseline**: Laplacian blur threshold > 100.0 + SCRFD + MiniFASNetV2 + ArcFace ResNet-50 (FP16/ONNX) + FAISS IndexFlatIP.
* **Целевые метрики**:
  * FAR <= 0.001% (10^-5)
  * FRR <= 1.0%
  * ROC-AUC / PR-AUC > 0.999
  * Latency p95 <= 100 мс, p99 <= 130 мс

## 8. Validation Strategy, Subgroups & Delayed Labels

* **Identity-disjoint Split**: Разбиение Train / Val / Test выполняется строго по person_id. Данные одного человека никогда не пересекаются между выборками для предотвращения Data Leakage.
* **Разнообразие условий**: Валидационная выборка включает кадры с разных точек прохода, с разной высоты, в разное время суток (утренний, дневной и контрсвет) и в разные сезоны (очки, шапки, шарфы).
* **Оценка по подгруппам**: Позадачный расчет FAR/FRR по полу, возрасту, наличию очков и уровням освещенности.
* **Delayed Labels**:
  * Ручные решения охраны (нажатия «Допустить» / «Отклонить») используются как разметка для кадров Серой зоны.
  * Проход по RFID-карте в течение 10 секунд после биометрического отказа (DENY) регистрируется как потенциальный False Reject.
  * Жалобы сотрудников связываются с логом по event_id для дальнейшего аудита.

## 9. Role of LLM in Access Control Architecture

Использование LLM в синхронном контуре принятия решений (ALLOW / DENY) полностью исключено. Принятие решения на проходной требует жесткого детерминизма, высокой скорости и нулевой толерантности к галлюцинациям.
